Project Overview

Project Title

ModernBooks Online Bookstore Platform

Website Category

E-Commerce / Digital Media Retail

Problem Statement

Traditional physical bookstores lack immersive, fast-loading, framework-less alternative storefronts optimized equally well across old and ultra-modern web browsers.

Selection Reason

Chosen to test the performance limits of modern layout engines (CSS Grid/Flexbox) and reactive local workflows (localStorage state) using raw JavaScript.

02 / 10

Project Description

ModernBooks is a fully client-side online bookstore built to prove that a polished, e-commerce-grade shopping experience does not require a framework. The application targets casual readers, students hunting for affordable editions, and gift-shoppers who want to browse by mood as much as by title — a demographic that responds well to fast filtering, visible pricing logic, and a shopping tray that never loses its contents on refresh. Architecturally, the frontend is split into three independent layers: a semantic HTML5 structure that remains readable without any styling, a CSS3 layer built entirely from custom properties so the glassmorphism theme and its light/dark variants share one source of truth, and a JavaScript state layer that owns the catalogue, cart, and wishlist as plain arrays synced to localStorage. Filtering, sorting, and rating interactions all run through pure array methods (filter, sort, reduce) rather than page reloads, so the shelf feels reactive without a virtual DOM. Looking beyond the competition brief, the same architecture could scale into a real storefront by swapping the static catalogue array for a fetch call to a headless commerce API, adding a checkout and payment step behind the existing cart ledger, and introducing account-based wishlists once authentication is layered on top of the current localStorage model.

Challenges Faced & Structural Resolutions

Cross-browser backdrop-filter support

The glassmorphism effect relies on backdrop-filter, which behaves inconsistently across older Chromium builds and requires vendor prefixing on WebKit.

Resolved by pairing every backdrop-filter declaration with a -webkit-backdrop-filter fallback and a solid semi-transparent background colour, so the layout degrades to a tinted panel rather than an invisible one on unsupported browsers.

Nested array mutation for cart deletions

Removing a single item from the cart array without mutating shared references caused stale badge counts and duplicate toast notifications during rapid clicking.

Resolved by rebuilding the cart as a fresh array on every mutation using Array.prototype.filter instead of splice, then re-rendering from that single source of truth so the UI, badge counts, and localStorage stay in sync on every call.

Sticky filter sidebar on tablets

A position: sticky sidebar collided with the collapsing grid on tablet widths, causing overlap with book cards.

Resolved in responsive.css by switching the sidebar to position: static with a wrapped flex layout below 900px, restoring sticky behaviour only on desktop viewports.

Persisting state without a backend

Cart, wishlist, and theme preference needed to survive page reloads with zero server involvement.

Resolved by centralising all mutable state in one state object and writing a single persist() helper that serialises it to localStorage after every state-changing action, with a matching hydration step on DOMContentLoaded.

Feedback Statement

This project sharpened our foundational JavaScript skills far more than any lecture-based module could — building the cart and filter systems from raw arrays forced us to actually understand state instead of importing it from a framework. The training's step-by-step build flow, from static markup to a fully interactive storefront, mirrored how real frontend teams incrementally ship features, and it left us confident that we can build accessible, responsive interfaces without leaning on a UI library as a crutch.

— Team ModernBooks
